# 智能语音问诊记录 · 医学生问诊实训与病史采集

喊一声「**小医小医**」（或者只说一遍「**小医**」）就开始采录，说完再补一句
「**录音完毕**」就存好 —— **全语音控制，不用碰键盘**。本地 VAD 自动断句 →
本地 ASR（SenseVoice / Whisper）转写 → DeepSeek 按 **SOAP** 格式整理成病历 →
SQLite 落库 → 网页看板实时出**可编辑的病历卡片**。

一次唤醒到说「下一段」之间的整段录音，汇总成**一张 SOAP 卡片**
（主诉 / 现病史 / 体格检查 / 诊断思考 / 诊疗计划），卡片生成后可以直接在网页上
点进去改 —— 改完点「💾 保存修改」落库，点「🔄 智能润色/推演」让带教视角的模型
补出诊断思考与诊疗计划；分几次记的碎片，勾上几张卡片点「🔗 合并选中项并重新整理」，
就能熔成一份完整的病历。

说错了？录音途中补一句「**作废**」这段就直接丢掉（不转写、不调 DeepSeek、不入库）；
嘴里不方便开口，就点网页状态栏上的 **⏹️ 结束并整理** / **❌ 放弃本条**；
网页上每条卡片右上角还有个「🗑️ 删除」，删库的同时会把 `my_memos.md` 一起对齐。

**听岔了也能用**：控制词判定走**拼音模糊匹配**，ASR 把「录音完毕」写成「錄音完畢」
「入音完畢」、「作废」写成「坐着飞」「錯誤費」、把「小医」写成「小一」「小依」，
一样照常触发；短到「完毕」「保存」「好了」「收工」也能收尾。

**医学术语有专门的纠错层**：内置 79 个医学热词（主诉、湿啰音、反跳痛、柏油样便、
急诊胃镜、心肌梗死…），faster-whisper 后端会在解码期就带着这些词听，
所有后端都会在识别后再按读音校正一遍。

```
 ┌──────────────────────────── 语音状态机 ────────────────────────────┐
 │                                                                   │
 │   ⚪ 待机中          🔴 正在录音         ⏳ 整理并生成病历          │
 │  （等待唤醒词）  ──►  （听到「小医」）──► （静音/「录音完毕」）     │
 │        ▲                        │  ▲                  │           │
 │        │        网页「⏹️ 结束并整理」/「❌ 放弃本条」     │           │
 │        └──────────────────────────────────────────────┘           │
 │              回到待机，等下一次唤醒（「退出录制」则整个退出）        │
 └───────────────────────────────┬───────────────────────────────────┘
                                 │
   ┌──────────────┐   ┌──────────┴────────┐   ┌────────────────┐
麦 ─►│  silero-vad  │──►│   录音缓冲         │──►│ 音频预处理      │──► DeepSeek
   │ 实时语音检测  │   │ 静音 3s 兜底截断   │   │ 去噪/增益 ↓     │   SOAP 整理
   └──────────────┘   └───────────────────┘   └────────────────┘       │
        ▲                          SenseVoice / whisper ＋医学热词提示 ▼
        └── tiny 模型后台扫指令 ─────────────────► memos.db (SQLite) ──► 网页看板
                                               │  拼音模糊匹配指令词      可编辑卡片
                                               │  识别后医学热词校正   智能润色/推演
                                               └──► my_memos.md（每条自动追加）
```

**隐私说明**：音频与识别全部在本机完成，**只有识别后的文本**会被发送到 DeepSeek。
如果没有配置 API Key，程序会自动降级到内置的规则整理，此时全程不联网。

不想用唤醒词？`python main.py --no-wake`（或 `.env` 里 `WAKE_WORD_ENABLED=false`）
就退回「一直听、听到人声就录」的免唤醒模式，适合一个人待着的安静房间。

## 一、环境要求

| 项目 | 要求 |
| --- | --- |
| Python | **3.10 及以上**（本项目已在 3.14.6 上完整验证：torch 2.12.1+cpu / silero-vad 6.2.3 / faster-whisper 1.2.1 / funasr 1.4.16） |
| 操作系统 | Windows / macOS / Linux |
| 麦克风 | 任意可用输入设备 |
| 网络 | 仅安装依赖与首次下载模型时需要；之后 ASR 可完全离线 |
| 存储 | 约 2.5 GB（PyTorch + Whisper base ~150 MB + **SenseVoiceSmall ~936 MB**；只装 whisper 可省下后两项） |
| CPU | 纯 CPU 可用，默认走 SenseVoiceSmall（非自回归，比 whisper 更快）；录音过程几乎不占 CPU |

> 如果你的 Python 版本较新而 `pip install torch` 卡在编译，说明官方还没放出该版本的预编译轮子，
> 换一个稍旧的 Python（如 3.12）即可；这不是本项目的问题。
> 本项目实测 **Python 3.14 下 torch / funasr 都有可用轮子**，不必为此降级。

## 二、安装

```bash
# 1) 创建虚拟环境（强烈建议，避免污染全局 Python）
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

# 2) 安装 PyTorch（CPU 版体积小很多；有 NVIDIA 显卡请去 pytorch.org 选 CUDA 版命令）
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cpu

# 3) 安装其余依赖
#    含 pypinyin（控制词/唤醒词的拼音模糊匹配）与 funasr（中文专用 ASR，默认后端）
pip install -r requirements.txt

# 4) 首次运行时自动下载 SenseVoiceSmall 权重（约 936 MB，本机实测约 6 分钟）
#    缓存在 %USERPROFILE%\.cache\modelscope，之后启动是秒级的
python main.py --doctor
```

> 只想装最小可用（不装 funasr、接受 whisper 的中文识别率）：
> `pip install sounddevice numpy silero-vad torch torchaudio faster-whisper pypinyin openai flask`，
> 并把 `.env` 里写 `ASR_BACKEND=whisper`。

**Linux 额外步骤**：`sounddevice` 依赖 PortAudio 系统库。

```bash
sudo apt-get install libportaudio2 portaudio19-dev   # Debian / Ubuntu
sudo dnf install portaudio-devel                     # Fedora
```

**macOS**：`brew install portaudio`，并确保「系统设置 → 隐私与安全性 → 麦克风」中授权终端。

编辑 `.env`，至少填入 API Key：

Key 在 <https://platform.deepseek.com/api_keys> 申请。其余参数在 `.env.example` 里
都有中文注释，按需修改即可。最常改的几项：

```ini
# 换唤醒词 / 关掉唤醒词
WAKE_WORD=小医小医
WAKE_WORD_ENABLED=true

# 医学热词：留空 = 用内置的 79 个；写 off = 整组关掉
ASR_HOTWORDS=
# 解码期提示词（**只有 faster-whisper 后端吃这个参数**）
ASR_INITIAL_PROMPT=true
# 识别后按读音校正医学术语（所有后端都生效）
ASR_HOTWORD_CORRECT=true
# 束搜索宽度：越大越准、越慢（CPU 上 5 是甜点）
ASR_BEAM_SIZE=5

# 各类语音指令（逗号分隔，中英文逗号都认）
SEGMENT_END_KEYWORDS=录音完毕,下一条,保存这段,这段保存
# 口语短结束词，只认句尾；不想要就写 off
SHORT_END_KEYWORDS=完毕,保存,好了,收工,就这样,就这些,说完了
EXIT_KEYWORDS=退出录制,停止运行,彻底结束
CANCEL_KEYWORDS=作废,取消,这条不要了,别记录了,不要了

# 静音多久算说完（毫秒）；续航吃紧或说话爱停顿可以调
VAD_SILENCE_MS=3000

# 语音识别：auto = 装了 funasr 就用中文专用的 SenseVoice，没装就退回 faster-whisper
ASR_BACKEND=auto
# 送进 ASR 前的音频预处理（去直流 + 降噪 + 响度归一只补不压），默认开
AUDIO_PREPROCESS=true
AUDIO_DENOISE=true

# 网页端口；想用手机在同局域网里看就改成 0.0.0.0
WEB_PORT=5000
WEB_HOST=127.0.0.1
```

> ⚠️ **请把 Key 填进 `.env`，不要填进 `.env.example`。** 程序只加载 `.env`；
> `.env.example` 是给人复制和提交的模板，写进去的密钥等于公开。`.env` 已被
> `.gitignore` 忽略。若密钥曾经进过 `git` 历史或分享出去，请到控制台吊销并重新签发。

### 唤醒词与语音指令

启动后程序停在**待机**，麦克风一直开着但**不记录任何内容**，直到听见唤醒词：

| 说什么 | 默认词 | 效果 |
| --- | --- | --- |
| **唤醒词** | 小医小医 / 小医 | 开始录音（`🔴 正在录音...`） |
| **分段结束词** | 录音完毕 / 下一条 / 保存这段 / 这段保存 | 立刻截断 → 转写 → 整理 → 落库 → **回到待机** |
| **短结束词**（只认句尾） | 完毕 / 保存 / 好了 / 收工 / 就这样 / 就这些 / 说完了 | 同上。口语里两三个字就能收尾，不用把"录音完毕"说全 |
| **作废词**（只认句尾） | 作废 / 取消 / 这条不要了 / 别记录了 / 不要了 | **直接丢弃这段**：不转写、不调 DeepSeek、不入库、不写 Markdown |
| **退出词** | 退出录制 / 停止运行 / 彻底结束 | 保存当前内容后**退出整个程序** |
| （兜底）静音 | 3 秒 | 忘了说"录音完毕"时的自动截断，效果同上 |

四条指令的优先级是 **退出 > 作废 > 分段 > 唤醒**：一口气说了好几个时，按这个顺序听
（"录音完毕，这条不要了" = 别存；"这条不要了，退出录制" = 丢掉这段然后收工）。

一次完整的使用长这样：

```
你：小医小医
    🔴 [正在录音...] (说「录音完毕/下一条」立即保存 · 或静音 3.0 秒自动保存)
你：患者主诉上腹隐痛三天。现病史：三天前吃了火锅后上腹持续隐痛，伴恶心呕吐。
    体格检查上腹压痛阳性。初步诊断急性胃炎。诊疗计划血常规加急诊胃镜，录音完毕
    ⏳ [录音结束，DeepSeek 按 SOAP 整理中...]
    💾 [已保存 #1]  ← 网页上出现一张 SOAP 病历卡片，八段都可以点开改
    ⚪ [待机中（等待唤醒词）]

你：小医                       ← 只说一遍也认
你：既往史高血压十年，下一条    ← 立刻存成第 2 条，时间戳各自独立
                                  （这句会落进「既往史」那一栏，不会跟个人史混住）
你：家族史无特殊               ← 这次什么结束词都没说（落进「家族史」那一栏）
    （静音 3 秒后自动保存为第 3 条）

你：小医
你：呃……那个，算了，这条不要了  ← 说到作废词，这段从内存里直接丢掉
    🚫 [本条已作废，未保存] 这段录音没有离开过本机内存
    ⚪ [待机中（等待唤醒词）]    ← 不调用 DeepSeek、不写库、不花一分钱

你：退出录制                   ← 保存后整个程序退出
```

四类默认指令词都可以在 `.env` 里改（`WAKE_WORD` / `SEGMENT_END_KEYWORDS` /
`SHORT_END_KEYWORDS` / `EXIT_KEYWORDS` / `CANCEL_KEYWORDS`，逗号分隔，中英文逗号都认）。
短结束词整组关掉写 `SHORT_END_KEYWORDS=off`（也认 `-` / `none` / `无`），
关掉之后就只剩长指令词能收尾，回到最保守的老行为。

**「小医」和「小医小医」都认，听岔了也认。** 叠词会自动折半 —— 喊一遍「小医」同样唤醒，
并且**两种长度各自**都能容忍同音错写。ASR 实测常把「小医」写成「小一」「小依」，
把叠词写成「小一小一」，程序对每个长度做**逐字同音全组合**（共 46 种写法）后再比对：

| 你实际说的 | ASR 可能写回来的 | 认不认 |
| --- | --- | --- |
| 小医 | `小一` / `小依` / `晓医` / `校医` | ✅ |
| 小医小医 | `小一小一` / `晓依` / `小依小医` | ✅ |
| 小记小记（上一版的词） | `小计小计` / `小纪小纪` | ❌ 已换词，不再唤醒 |

表里没有的字用 `WAKE_ALIASES` 自己补。**反过来的坑**：正因为放宽了字面层，
拼音那一层反而收紧了 —— 它只用整词别名，否则正文「明天取**消**会**议**」
（qu-**xiao** hui-**yi**）里的两个音隔着字也会被算成说全了，那就误唤醒了。

**作废词/短结束词只认句尾。** "取消"在正常内容里是常用动词（"明天取消会议，改到周四"），
"保存"也是一样（"文件我已经保存了副本"）—— 一旦误判，你说的一整段就白说了。
所以这两类词只在**句尾**那一下生效："作废"/"算了作废吧"/"刚才那段别记录了"都算，
正文里的"把旧方案作废以后重新做""文件我已经保存了副本"都不算。
句尾匹配会自动吃掉后面的语气字（吧/了/啊），所以"买牛奶**保存了**"照样收尾。

> 代价写在明处：短结束词挂在句尾时会被当成指令 —— "我这边已经**保存了**"会被截断落库
> （正文保留"我这边已经"）。这是"允许两三个字收尾"必然的代价；不想要就把
> `SHORT_END_KEYWORDS` 设成 `off`，只用长指令词。
> 默认词表里**故意没有"结束"**："会议结束了"是最常见的正文，句尾匹配会把整条备忘清空。
> 想说"结束"收尾就把它加进 `SEGMENT_END_KEYWORDS`。

#### 为什么错别字也能触发（拼音模糊匹配）

结束词失效的根因不是"没说清楚"，而是 **ASR 写错了字**。把 SAPI 合成语音真喂给
faster-whisper `base`，拿到的实测结果是：

| 你实际说的 | ASR 写回来的 |
| --- | --- |
| 录音完毕 | `錄音完畢` / `入音完畢` |
| 保存这段 | `保存這段` |
| 退出录制 | `退出錄製` |
| 作废 | `坐着飞` / `錯誤費` |
| 这条不要了 | `這條不要了` |
| 小医 | `小一`（tiny 模型实测稳定听成这个） |

逐字比对这些**全是错的**，但读音几乎一模一样。所以控制词判定多了一层
**拼音匹配**（`pip install pypinyin`，装上自动生效）：

1. 把识别文本逐字转成拼音，标点空白保留占位 —— **下标与原文严格一一对应**，
   命中之后才知道该从原文里剪掉哪几个字（"錄音完畢"按字面是删不掉的）；
2. 做**音近归一**：`zh/z`、`ch/c`、`sh/s` 整组折叠，前后鼻音 `ang/an`、`eng/en`、
   `ing/in` 折叠，再加一张极短的近音表（`录/入`、`作/错`、`收/搜`）；
3. 用**覆盖度**而不是相似度比对：ASR 会凭空多塞音节（"作废" → "坐着飞" = zuo-zhe-fei），
   关键词的读音按顺序全都出现就算命中 —— 覆盖度 1.0，而整体相似度只有 0.69，后者会漏判；
4. 窗口宽度只试 `n` 和 `n+1` 两种，多的那一个音节正好兜住"作废**吧**""就这些**了**"；
5. 多个候选同时命中时取**最长**的那个，否则"錄音完畢"会被短的"完毕"先命中，
   只剪掉后半截、正文里剩一个孤零零的"錄音"。

同一套逻辑也用在**入库清洗**上：判定命中的同时按下标把控制词从原文里剪掉，
所以 `錄音完畢` 这类写法不会有一截漏进正文，也不会跑进 DeepSeek 的标题/摘要里。

> 没装 pypinyin 也能跑，只是退回逐字模糊匹配（弱一档）。`--doctor` 会告诉你当前有没有生效。
> 拼音匹配也顺手解决了繁体字：錄/录、畢/毕、這/这 的拼音本来就相同，不用单独维护一张繁体表。

**所有指令词都不会进入正文。** 唤醒词被吃掉的是开头那一截，结束词/退出词/作废词只剥真正在
起终止作用的那些 —— 句中的同名实词原样保留（"**会议结束之后**给我打电话"里的"结束"是内容）。
剥完才送 DeepSeek，所以标题/摘要/待办里不会混进"下一条""退出录制"之类的东西。

```
┌──────────────────────────────────────────────────────────
│ 备忘录 #1（整理方式：DeepSeek）
├──────────────────────────────────────────────────────────
│ 时间：2026-10-08 10:00:00
│ 标题：明天下午与客户开会
│ 分类：工作
│ 摘要：明天下午三点与客户开会，需提前准备方案并通知张总。
│ 待办：
│   1. 提前准备好会议方案  （截止 2026-10-09 15:00）
│   2. 发邮件给张总  （截止 2026-10-09 15:00）
└──────────────────────────────────────────────────────────
```

### 录音状态一眼可见

终端会用一个醒目的分隔线把「当前状态」框出来，状态一变就重画一次，
并伴随一声蜂鸣（Windows 控制台会响，部分终端会忽略；`--no-beep` 可关）。
**同一个状态也会实时出现在网页看板上**，两处永远一致。

```
══════════════════════════════════════════════════════════════
 ⚪  [⚪ 待机中（等待唤醒词）]
      说「小医」开始记录 · 说「录音完毕/下一条/保存这段」保存并回到待机
      说「退出录制/停止运行」保存后退出 · 静音 3.0 秒自动保存 · Ctrl+C 退出
══════════════════════════════════════════════════════════════

 🔴 [正在录音...] (说「录音完毕/下一条」立即保存 · 或静音 3.0 秒自动保存)

 ⏳ [录音结束，DeepSeek 整理中...] （本条处理期间暂停收音，请稍候）

 ...（转写 + 整理结果打印在这里）...

 💾 [已保存 #1]

      ← 自动回到上面的 ⚪ 待机界面，等下一次唤醒
```

| 图标 | 状态 | 含义 |
| --- | --- | --- |
| ⚪ | standby | 待机，等你喊唤醒词 |
| 🔴 | recording | 已唤醒，正在录音 |
| ⏳ | processing | 已截断，正在转写 / 调 DeepSeek 整理 |
| 💾 | — | 已落库（并已追加进 Markdown） |
| 🚫 | — | 语音作废：这段被丢弃，什么都没写 |
| 🎙️ | standby | 免唤醒模式下的「正在倾听」（`--no-wake`） |

> 提示文案跟着**实际生效的开关**走：开了 `--early-stop` 才会写「或说"结束"提前截断」，
> 关着唤醒词才会写「请直接说话，无需唤醒词」，不会承诺做不到的事。

### 连续录音（默认行为）

**不需要任何额外操作** —— 存完一条后自动回到待机，你直接喊下一声「小医」就行，
不用重启、不用按键、不用等它。两条之间的间隔、说话时长都没有限制。

会跳出这个循环的只有两种：说「**退出录制**」（保存后体面退出），或者按 `Ctrl+C`。

### 纯 CPU 也能跟得上（性能设计）

断句和识别是两件事，分开看就清楚了：

| 环节 | 谁在做 | 代价 |
| --- | --- | --- |
| **断句**（什么时候算说完） | silero-vad | 只算人声概率，**不碰 ASR**，每 32ms 一块，几乎不占 CPU |
| **唤醒/指令**（有没有说"小医"） | faster-whisper `tiny` | 后台线程、每 0.6 秒最多一次、每次只看最近 2.2 秒 |
| **识别**（说的什么） | SenseVoiceSmall 或 faster-whisper | 一条几秒的录音耗几百毫秒到数秒，**只在那一段结束之后跑一次** |

唤醒词识别天生要"听文本"，所以它必然要跑 ASR —— 但代价被压到了最低：
用 `tiny`（比 `base` 又快一倍）、**只看最近 2.2 秒的滑动窗口**（不是把整段录音re-识别一遍）、
**同一时刻只允许一次扫描在飞**、而且**只在检测到人声时才扫**（没人说话时一次都不跑）。
真麦克风不说话的时候，CPU 基本是 0。

录音**已经唤醒之后**的指令扫描（听"录音完毕/退出录制"）同样是后台线程 + 只看尾部窗口，
主循环一秒都不会被它挡住。

围绕这一点做了五件事：

1. **默认模型 `base`**（不是 `small`）。CPU 上快 2~3 倍、权重小 3 倍，短句备忘足够用。
2. **指令扫描全在后台线程**。Whisper 再快也要几百毫秒，直接在主循环里跑会卡住 VAD
   状态机 → 队列积压 → 丢块 → **连静音断句都会一起失灵**
   （丢块会让 VAD 的"静音累计"失真，3 秒永远数不满）。
3. **默认关掉"结束/完毕"提前截断**（`EARLY_STOP_KEYWORD`）。唤醒词模式下有"录音完毕"
   这类明确指令词，用不着再靠反复转写去猜"结束"，纯 CPU 上没必要付这份钱。
4. **处理期间暂停采集**。上一条在转写/整理时，采集线程只把设备缓冲读走、不入队，
   队列因此不会积压，也不会为了腾地方丢块。处理完立刻恢复，不用重开麦克风。
5. **万一真的丢块了会自愈**。丢弃时打个"断点"标记，主循环据此作废当前这段、
   重新开始倾听，而不是让 VAD 一直等一个永远等不到的 `end`。

> 免唤醒模式（`--no-wake`）下如果还想用"说结束就停"，加 `--early-stop` 打开即可 ——
> 探测同样跑在后台线程（但纯 CPU 上仍会明显增加负载，`--doctor` 会提醒你）。

### 想更准？换中文专用 ASR（可选）+ 音频预处理（默认开）

识别不准有两个来源：**模型不懂中文**和**声音太小声/太吵**。两边都给了开关。

**① 音频预处理（默认开，纯 numpy，不装任何额外依赖）**

每段音频送进 ASR 之前先整一遍：

| 步骤 | 做什么 | 为什么 |
| --- | --- | --- |
| 去直流 | 减掉整段的均值 | 有些声卡有直流偏置，会让识别飘 |
| 谱减降噪 | 用能量最低的 20% 帧估出稳态噪声谱，逐帧减掉（保留相位、保留 18% 原始幅度下限） | 空调/风扇/机箱的底噪是识别率杀手；保留幅度下限是为了不把 s/sh/f 这类清辅音也一起抹平 |
| 响度归一 | **只往上补**到 -3 dBFS，上限 +18 dB | 对着远一点的麦克风小声说话时提升最明显 |
| 削峰保护 | 峰值超过 0.99 就等比压回来 | 补太狠会削顶破音 |

"只往上补、绝不往下压"是刻意的：本来就录得够响的音频不该再被打一遍，
少一次改动信号的机会就少一次出错的机会。每一步都包在 `try` 里，
**任何一步出意外都只是少做一步**，绝不会因为预处理失败把一段录音弄丢。

配置项：`AUDIO_PREPROCESS=false` 整组关掉、`AUDIO_DENOISE=false` 只留归一、
`AUDIO_TARGET_DBFS` / `AUDIO_MAX_GAIN_DB` 微调。

**② 换中文专用模型（默认就是它）**

```bash
pip install funasr      # 已包含在 requirements.txt 里，正常安装就有
```

`.env` 里保持 `ASR_BACKEND=auto` 即可，程序会自动切到 **FunASR / SenseVoiceSmall**：

| 后端 | 特点 | 怎么选 |
| --- | --- | --- |
| `funasr`（SenseVoiceSmall） | **中文专用**、非自回归，CPU 上比 whisper 快且更准，直接出标点、还能把"三点"规整成"3点" | 装了 `funasr` 就自动用它 |
| `whisper`（faster-whisper） | 通用多语言，`base` 档小又快 | 没装 `funasr` 时的默认，也是老环境的样子 |

代价说清楚：`funasr` 会带入 numba / llvmlite / librosa / modelscope 等依赖（几百 MB），
首次运行还要下载约 900MB 的模型权重。**不装也完全能用** —— `auto` 会安安静静退回
faster-whisper，行为和这一版之前一模一样。想强制指定就写 `ASR_BACKEND=funasr` 或 `whisper`，
`python main.py --doctor` 会打印当前实际生效的后端。

> `--model` 参数只在 whisper 后端生效；切到 funasr 后模型名看 `ASR_FUNASR_MODEL`。

### 医学问诊模式：热词提示 + SOAP 病历 + 可编辑卡片

这一节是给**问诊实训与病史采集**用的三个专门改动。

#### ① 医学热词（两层，作用点不同）

内置 79 个医学热词，覆盖问诊栏目、症状、体征、解剖部位与检查项目：

```ini
ASR_HOTWORDS=     # 留空 = 用内置词表；写 off / - / none / 无 = 整组关掉
```

它们有**两个用途，但吃的不是同一段**：

| 用途 | 生效条件 | 覆盖范围 |
| --- | --- | --- |
| **解码期提示词**（`initial_prompt`） | **只有 faster-whisper 后端**（`ASR_INITIAL_PROMPT=true`） | 前 46 个词左右 |
| **识别后校正**（`correct_medical_terms`） | 所有后端，`ASR_HOTWORD_CORRECT=true` | 全部 79 个词 |

⚠️ **词表顺序就是优先级** —— 提示词按顺序往 `initial_prompt` 里塞，塞满 220 字就停。
排在前面的当解码提示词，排在后面的只参与识别后校正。所以词表按**梯队**排，
不是按分类排：第一梯队（问诊栏目 + 黑便/血常规/急诊胃镜/胃溃疡/心肌梗死等高频词）
要能独立塞满提示词，尾部超出预算的那批只靠校正兜底。自检里有断言盯着这件事。

**反义词对必须成对留下**（右上腹/右下腹、干啰音/湿啰音、呕血/咯血）：
只留一个的话模型就失去了区分能力，宁可两边都不喂。

⚠️ **解码期提示词只对 faster-whisper 生效。** `auto` 在本机装了 funasr 之后会落到
**SenseVoiceSmall**，而它**没有 `initial_prompt` 参数** —— 也就是说默认配置下
这条优化是静默失效的，真正兜住医学术语的是下面这层识别后校正。
需要解码提示词就显式写 `ASR_BACKEND=whisper`（代价是中文识别率本身略降）。

#### ② 识别后校正（后端无关）

不管哪个后端，识别完都会再过一遍**按读音的医学术语校正**：
要求**完全同音（相似度 1.0）+ 字数相等 + 至少共享一个字**，三个条件同时满足才替换。
门槛卡这么死是因为改病历比不改更危险 —— 宁可漏改，也不能把「主诉」改成别的词。

举几个实测的例子：

| 识别结果 | 校正后 | 说明 |
| --- | --- | --- |
| 湿罗音 | 湿啰音 | 啰/罗 完全同音 |
| 心机梗死 | 心肌梗死 | 同上 |
| 胃境 | 胃镜 | 同上 |
| 血长规 | **改不动** | pypinyin 给「长」取 zhǎng 音（zan），与「常」can 不同 —— 这正是解码提示词要补的地方 |
| 麦氏点、反跳痛 | 保持原样 | 本来就对，不动 |

#### ③ SOAP 病历格式

DeepSeek 的提示词按 **SOAP** 组织输出，一次唤醒到说「下一段」之间的完整录音
汇总成**一张卡片**。八个字段按病历书写规范排列：

| 段落 | 库里的列 | 说明 |
| --- | --- | --- |
| 主诉 | `chief_complaint` | 一句话概括，含时长 |
| 现病史 | `history` | 按 1. 2. 3. 4. 分条的起病经过 |
| 📋 既往史 | `past_history` | 患者本人得过什么病：既往疾病、手术史、外伤史、药物过敏史 |
| 👤 个人史 | `personal_history` | 患者本人怎么生活：烟酒嗜好、职业暴露、地方病史 |
| 👨‍👩‍👧 家族史 | `family_history` | 他的亲属：直系亲属患病与家族遗传病、同类疾病史 |
| 体格检查 | `physical_exam` | 生命体征与阳性体征 |
| 诊断思考 | `assessment` | 初步诊断与鉴别方向 |
| 诊疗计划 | `plan` | 拟完善的检查与处理 |

> **既往史 / 个人史 / 家族史为什么必须三栏分开？**
> 因为这三栏回答的是**不同的人**：既往史问「患者本人得过什么病」，个人史问
> 「患者本人怎么生活」，家族史问「他的亲属」。判据只有一条 —— **这句话说的是谁**。
> 合在一栏就得靠模型去猜哪一句该归哪栏，而「父亲吸烟」和「本人吸烟」写反了，
> 是带教老师一眼就能挑出来的错。提示词里 `_HISTORY_SPEC` 把这三栏的定义与三条硬规矩
> （不许串栏 / 没提到的段留空、不要写「无特殊」「未提及」占位 / 这三段是事实不是推演）
> 写死，且被书记员提示词与合并提示词**逐字共用**。

**空串 = 「还没问到」，这是唯一口径。** 提示词明确要求模型**不要**往空字段里写
「未提及」三个字 —— 一旦写进去，就再也分不清「他问了，患者说没有」和「他压根没问」。
前端用 CSS 的 `:empty::before` 把空段画成灰色的 **「未提及 · 点击补充」**，
这句话**只在 CSS 里画、绝不进 DOM**：真写进 DOM 的话，一按保存就把「未提及」
存成病历内容了。这正好也起到「还缺哪几栏」的提示作用。

旧的「标题/分类/摘要/待办」结构**完全保留**：老记录照常显示，
没有 SOAP 内容时八段就是空串而不是 `None`，所以老库升级不会报错
（SOAP 列用 `ALTER TABLE ADD COLUMN` 迁移 —— O(1)、非破坏性、可重复执行）。

#### ④ 卡片直接改：💾 保存修改 + 🔄 智能润色/推演

网页上的病历八段和「标题/摘要」都是 `contenteditable="true"`，**点进去就能改**
（三条病史同样可点可改），卡片标头上有两个按钮：

| 按钮 | 作用 | 接口 |
| --- | --- | --- |
| **💾 保存修改** | 把卡片上的手工修改写进数据库，并同步重刷 `my_memos.md` | `POST /api/memos/update/<id>` |
| **🔄 智能润色/推演** | 交给 DeepSeek 做临床推理，推出**诊断思考**与**诊疗计划** | `POST /api/memos/re-summarize/<id>` |
| **🔗 合并选中项并重新整理** | 把勾选的多条记录熔成**一张新的**完整 SOAP 病历卡片 | `POST /api/memos/merge` |

**加一个病历字段只需要改一张表。** 卡片渲染、保存白名单、润色白名单、合并的取数范围、
Markdown 导出、Word 导出六处全部派生自 `main.SOAP_SECTIONS`
（`webui.py` 里的 `EDITABLE_FIELDS` / `REGENERATE_FIELDS` / `has_soap` 都是从它算出来的），
所以本次把五段扩成八段、新增三条病史时，**`webui.py` 一行都不用改**。
标题与图标也是分开存的：`SOAP_SECTIONS` 里只有纯中文标题（要原样进 Markdown 与 Word，
病历文书里不该印 emoji），emoji 单独放在 `SOAP_ICONS`，只在前端渲染时贴上去。
| **⏹️ 结束并整理 / ❌ 放弃本条** | 与录音状态栏上那两个按钮同义（见下节） | `POST /api/control/finish\|cancel` |

> 早先的 `/api/memo/<id>/update` 与 `/api/memo/<id>/regenerate` 保留为**别名**
> （同一个视图函数挂两条 url rule），老书签和浏览器缓存的旧页面都还能用。

**「智能润色/推演」不是"重写一遍"，是换了一个角色。** 首次整理用的是书记员提示词
（`SYSTEM_PROMPT`：只许如实记录，一个字都不许多），推演用的是带教医师 / OSCE 考官
提示词（`CLINICAL_PROMPT`），要求学生**在他已经写下的材料上**做临床推理：

| 段落 | 推演要求 |
| --- | --- |
| 诊断思考 | ① 最可能的初步诊断（附依据）② 1-3 个鉴别诊断，**分别写支持点与不支持点** ③ 信息不足时给"……待查"方向 + 该追问的问题 |
| 诊疗计划 | ① 建议加查的项目，**每项写清查它是为了排除或证实什么** ② 治疗处置（要不要留观/会诊）③ 护理观察、危险信号与随访 |

三条铁律写在提示词里：**不许凭空创造临床事实**（没问到的体征不许补）、
**诊断只写"待排/待查"口径**（这是教学演练，不是确诊报告）、**忠于学生的修改**。

> **三条病史必须出现在 `CLINICAL_FACT_FIELDS` 里** —— 这是本次改动里最危险的一处。
> 这个集合的作用是把"所有片段里都空着的段"分成两句话告诉模型：落在集合里的说
> 「这几段他没写到，不要替他补上」，落在集合外的说「这正是要你推演的部分」。
> 三条病史要是漏在这个集合外，模型就会**开始编患者的烟酒史和家族史** ——
> 而这两样恰恰是最容易被"合理推测"出来的。自检里有一条断言专门盯着它。
>
> 推演提示词里还刻意**不许模型"挪栏目"**：原本想允许"放错了可以挪到正确的那一栏"，
> 但那会与 `restore_edited_fields` 打架 —— 学生手改过的值在代码层会被原样还原，
> 结果是同一件事在两栏各留一份，读起来像父子俩都有高血压。改成"原样留在原来那一栏，
> 只有他空着没写的那几栏你才可以补"。

**「忠于修改」是代码保证的，不只是提示词里的一句话。** 页面会记录你**亲手打过字**的字段
（`touched`），推演返回后这几段被强制还原（`restore_edited_fields`）—— 模型出于
"帮你规范一下"的好意改掉的描述会被改回来，完成的提示里也会告诉你保留了几段。
诊断思考与诊疗计划**刻意不在保护名单里**：学生自己写了还按推演，说明他想看老师的思路。
请求里没有 `touched`（浏览器缓存的旧页面）时按"全都当改过"处理 —— 少润色几段只是效果打折，
拿模型结果盖掉学生核对过的描述却是真丢东西。

推演期间卡片会盖一层 **⏳ 正在调用 DeepSeek 进行医学推理…** 的加载动画；
完成后卡片平滑重画并高亮一下，被原样保留的段落左边补一道绿条（鼠标悬停有说明）。

推演走的是 `REGENERATE_FIELDS` 白名单，比手工可改的 `EDITABLE_FIELDS`
多出 `category` 与 `todos`：这两个不给手工改（待办是数组、分类是枚举，
做成 `contenteditable` 一改就坏），但模型重新生成时理应一并刷新。
**两个白名单是 UPDATE 列名的唯一来源**，这是 SQL 注入的防线，不是可选项。

手改的内容会被**优先**放进提示词（以 JSON 形式传全量数据，空段以 `""` 出现，
模型据此才知道该不该走"待查"），原始语音附在最后并降级为"仅作参考"；
重刷文档（`my_memos.md`）是异步收尾的一部分，不改 `raw_text`、也不改 `record_time`。

#### ⑤ 多选合并：🔗 合并选中项并重新整理

问诊常常是分几次记的：先记主诉，追问完再补一段现病史，体查又单独说一段。
每张卡片左上角都有**勾选框**，勾上 2 条以上，工具栏上的
**🔗 合并选中项并重新整理** 就会亮起来（不足 2 条时是灰的 —— 只合并一条等于
"重新润色"，该点的是那张卡上的 🔄），点下去交给 `MERGE_PROMPT` 熔成**一张新卡片**：

| 环节 | 做什么 |
| --- | --- |
| 取数 | `memo_ids` 去重后逐个查库，有一条不在（别的标签页删了）就整个 **404** 报出来 |
| 拼接 | 按 `memo_sort_key`（`record_time` 升序，同一秒按 id）逐段标注时间与出处 |
| 调模型 | `MERGE_PROMPT`：**资深临床带教导师**，"去粗取精、融会贯通"成标准 SOAP 病历 |
| 落库 | `insert_memo` 新起一条 + 重刷 `my_memos.md` + `publish_memo` 广播给所有页面 |

**这是"整理成一份"，不是"改写成一条"—— 源记录一条都不删。** 学生可能还要回头对照
自己当时记的原话；真要清理，卡片上本来就有 🗑️ 删除，由他自己决定。
合并结果在页面上排在自己那几段碎片**上面**（时间取最晚那段、id 又最大），
"汇总卡 + 底下几段原记录"自然成一组。

**去粗取精要真的去掉重复，但事实一个字都不许变。** 这就是合并提示词与润色提示词
最大的差别：润色的纪律是"别动学生写下的字"，合并的纪律恰恰是"该动就动"——
不去重合成就没有意义。所以提示词里写的是：同一件事说过几遍只留最完整的那次、
时间线并成一条、前后说法不一致的以**更晚**那段为准并注明"（后次记录更正）"，
但**所有细节都必须来自这几段记录，没出现过的发现一个字都不许加**。

两份提示词的角色不同，但**临床推理的要求逐字共用同一段常量**
（`_HISTORY_SPEC` / `_DIAGNOSIS_SPEC` / `_PLAN_SPEC` / `_OUTPUT_SPEC`）——
这几段是医学安全的护栏，抄成两份迟早改一漏一，而漏掉的那一份，模型就照着漏掉的那版做。
拼接一律用 `+` 而不是 f-string：`_OUTPUT_SPEC` 正文里有 `{"task": …}` 这样的 JSON 示例，
f-string 会把花括号吃掉。

合并期间工具栏上显示 **⏳ 正在调用 DeepSeek 融会贯通合并病历...**，复选框同时锁住
（免得等待时改了勾选，以为改动能影响到这次请求）；完成后新卡片平滑插入并高亮，
提示 **✨ 多次记录已成功合并为一张新病例卡片**。模型返回了合法 JSON 但八段全空时
按**失败**处理（502、不落库）—— 这种"成功"的假象比报错更糟：页面上会多出一张
空卡片，而学生以为合并好了。

python main.py --web                 # 默认 http://localhost:5000
python main.py --web --port 8080     # 换端口

浏览器打开后你会看到：

- **顶部状态胶囊** —— `⚪ 待机中` / `🔴 正在录音中...` / `⏳ 正在整理并生成卡片...`，
  带一颗会呼吸的指示灯，跟着麦克风的真实状态实时变化；
- **⏹️ 结束并整理 / ❌ 放弃本条（只在录音时出现）** —— 就在状态胶囊旁边，
  说不出指令词、或者旁边有人不方便开口时的**双保险**（见下）；
- **唤醒词提示条** —— 当前唤醒词、分段结束词、退出词、作废词、静音秒数，一眼看清怎么用；
- **卡片流（按时间倒序）** —— 每张卡片有开始时间戳（`YYYY-MM-DD HH:mm:ss`）、分类标签、
  标题、摘要、待办清单，以及一个可折叠的**「原始语音文本」**（点开才看到 ASR 原文）；
- **SOAP 病历八段（可直接编辑）** —— 主诉 / 现病史 / 📋 既往史 / 👤 个人史 /
  👨‍👩‍👧 家族史 / 体格检查 / 诊断思考 / 诊疗计划，点一下就能改（`contenteditable`），
  卡片标头带 **💾 保存修改** 与 **🔄 智能润色/推演** 两个按钮；
  还没问到的段显示成灰色的「未提及 · 点击补充」，就地就能补写；
- **勾选框 + 🔗 合并选中项并重新整理** —— 卡片左上角勾选，工具栏上的合并按钮
  跟着亮/灰（不足 2 条点不动），勾选状态挂在页面级、卡片被 SSE 重画也不会丢；
- **🗑️ 删除按钮** —— 每张卡片右上角，点一下二次确认，再删；
- **一键导出** —— 「导出 Markdown」「导出 Word」两个按钮直接下载整份历史文档；
- **手动输入框** —— 不想说话时打几个字回车，同样走完整的整理 + 落库链路。

页面**不需要手动刷新**：状态变化、新卡片、**删除**都由后端通过 **SSE**（Server-Sent Events）
主动推过来，新卡片会从顶部滑入并高亮一下，删掉的卡片淡出后消失、右上角计数自动减一。
在手机和电脑上同时开着这个页面时，一边删、另一边也会同步消失。断线时 `EventSource` 会自动重连。

#### 一键收尾：⏹️ 结束并整理 / ❌ 放弃本条

正在录音时，状态胶囊旁边会冒出两个按钮（待机时自动隐藏，免得误点）：

| 按钮 | 作用 | 接口 |
| --- | --- | --- |
| **⏹️ 结束并整理** | 立刻截断当前这段录音 → 转写 → 送 DeepSeek 整理 → 落库，等同说了"录音完毕" | `POST /api/control/finish` |
| **❌ 放弃本条** | 直接丢弃这段：不转写、不调 DeepSeek、不入库、不写 Markdown，等同说了"作废" | `POST /api/control/cancel` |

```bash
curl -X POST http://localhost:5000/api/control/finish
# {"ok":true,"action":"finish","state":"recording"}
curl -X POST http://localhost:5000/api/control/cancel
# {"ok":true,"action":"cancel","state":"recording"}
```

设计上有三件事值得说明：

1. **Web 线程只置一个标志位**，绝不碰音频缓冲 —— 真正的收尾（截断、转写、落库或丢弃）
   由录音主循环下一轮完成。否则网页线程会和 VAD 状态机抢同一个缓冲，
   轻则丢一段音频，重则把静音计时搅乱。
2. **不在录音时返回 409**，没有麦克风的进程（`--no-mic`）返回 503 —— 不假装成功，
   更不会凭空造出一段空录音。前端会把原因原样弹出来。
3. **两个请求同时到达时以"结束"为准**（两台设备几乎同时点的情况）：宁可多留一段，
   也不要因为一次竞态把刚说的话整段丢掉。

「放弃」是不可逆的，所以前端先弹一次二次确认；点完之后立刻回待机，可以继续喊唤醒词。

#### 删除一张卡片

点卡片右上角的「🗑️ 删除」→ 确认 → 卡片淡出，同时发生三件事：

1. 从 SQLite 删掉那一行；
2. **按数据库现状重刷 `my_memos.md`** —— 那个文件平时是「只追加」的，直接删库并不会让它
   少一段，所以这里整份重写，保证文档和数据库永远对得上；
3. 广播给所有打开的页面，各自把那张卡片移除、把「本次已记录 N 条」减一。

也可以直接打接口（删完返回剩余条数，顺带告诉你 Markdown 是否同步了）：

```bash
curl -X DELETE http://localhost:5000/api/delete/3
# {"ok":true,"id":3,"title":"明天下午与客户开会","remaining":2,
#  "markdown_path":"my_memos.md","markdown_synced":true}
```

> ⚠️ 删除**不可撤销**（界面上的二次确认就是为这个）。删错了只能重新说一遍。
> 另外注意：删掉的是**数据库里的记录**，如果这条早先已经被你复制进别的笔记软件，那边不会跟着变。

Web 层自己不写 SQL：转写、整理、落库走 `MemoPipeline`，删除走 `remove_memo`，
所以页面崩了、关了、卡住了都不会影响录音和数据。

需要 `pip install flask`（已包含在 `requirements.txt` 里）。没装 Flask 也不影响
命令行模式，只是 `--web` 会提示你先装。

### 导出文档

每条新备忘录在写入 SQLite 的同时，会**自动追加**一份到 Markdown 文件
（默认 `my_memos.md`，由 `.env` 里的 `MARKDOWN_PATH` 控制，留空或 `--no-md` 可关闭）。
因此你随时有一份可直接阅读、可同步到笔记软件的纯文本记录。

需要把历史一次性导出成完整文档时：

```bash
# 把库里所有记录导出成一份排版好的 Markdown（整体重写，可反复执行）
python main.py --export-md memos.md

# 导出 Word 文档（需要额外装：pip install python-docx）
python main.py --export-docx memos.docx

# 不带参数时用默认文件名
python main.py --export-md          # → memos.md
python main.py --export-docx        # → memos.docx
```

导出的文档长这样，含统计头部、每条一个二级标题、待办用复选框列表、并附上识别原文：

```markdown
# 我的语音备忘录

> 由 voice-memo 自动生成 · 共 3 条记录 · 导出时间 2026-10-08 15:12

## 1. 明天下午与客户开会

- **时间**：2026-10-08 10:00:00
- **分类**：工作

**摘要**：明天下午三点与客户开会，需提前准备方案并通知张总。

- [ ] 提前准备好会议方案 —— 截止 2026-10-09 15:00
- [ ] 发邮件给张总 —— 截止 2026-10-09 15:00

*原始识别原文*：嗯那个明天下午三点要跟客户开会记得提前准备方案

```

### 没有麦克风怎么测？用 `--replay` 灌一段音频

`--replay` 把 WAV 文件当作麦克风输入喂给 **同一条真实的 VAD 监听链路**，
走的是完全一样的断句/转写/整理/落库代码，只是音频来源换成了文件。
配合 `--replay-loops` 可以验证「连续录音」—— 同一段音频放 3 遍，
就应该自动产出 3 条备忘录，每条的时间戳各自独立。

```bash
# 准备好一个 16 位 WAV（任意采样率/声道，程序会自动转成 16k 单声道）
# 然后：回放 3 遍，产出 3 条记录
python main.py --replay sample.wav --replay-loops 3 --db demo.db

# 英文音频记得带上语言，否则会按 .env 里的 zh 去识别，结果是乱码
python main.py --replay english.wav --language en --replay-loops 2 --db demo.db

# 跑完看看确实存进去了几条
python main.py --db demo.db --list 10
```

## 五、数据表结构

```sql
CREATE TABLE memos (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    record_time     TEXT NOT NULL,   -- 开口说话的那一刻 YYYY-MM-DD HH:MM:SS
    raw_text        TEXT NOT NULL,   -- ASR 原始文本（已剔除控制词）
    title           TEXT,            -- 标题（≤20 字）
    category        TEXT,            -- 工作/生活/学习/购物/健康/财务/社交/灵感/其他
    summary         TEXT,            -- 摘要
    todos           TEXT,            -- 待办，JSON 数组字符串
    chief_complaint  TEXT,           -- 病历 · 主诉
    history          TEXT,           -- 病历 · 现病史
    past_history     TEXT,           -- 病历 · 既往史（患者本人的过去）
    personal_history TEXT,           -- 病历 · 个人史（患者本人的生活与接触）
    family_history   TEXT,           -- 病历 · 家族史（患者亲属的情况）
    physical_exam    TEXT,           -- 病历 · 体格检查
    assessment       TEXT,           -- 病历 · 诊断思考
    plan             TEXT,           -- 病历 · 诊疗计划
    created_at      TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);
```

> 后 8 列是**后加的**：老库第一次启动时用 `ALTER TABLE ADD COLUMN` 逐列补上，
> O(1)、非破坏性、可重复执行（自检里有迁移 + 幂等的用例）。
> **三条病史是三个独立的列，不是一段文字里的三个小标题** —— 它们回答的是不同的人
> （患者本人的病 / 患者本人的生活 / 他的亲属），分开存才谈得上分开渲染、分开编辑、
> 分开导出，也才谈得上让模型不去猜"这句话说的是谁"。
> 没有病历内容时这八列是空串而不是 `NULL` —— 让「没这一段」在所有出口只有一个表示。

`record_time` 记录的是**音频块的采集时刻**，而不是处理完成时刻 —— 采集在独立线程里带时间戳
入队，因此即使 ASR + LLM 耗时好几秒，时间也不会跑偏。

用 SQL 直接查：

```bash
sqlite3 memos.db "SELECT record_time, title, category FROM memos ORDER BY id DESC LIMIT 5;"
sqlite3 memos.db "SELECT json_extract(todos, '$[0].task') FROM memos;"
```

## 六、自检

```bash
python selfcheck.py
```

十一组、496 个检查点的**离线**自检（不需要麦克风、不需要 API Key、不需要装 torch；
全线通过约 33 秒）：

1. **文件完整性** —— 交付文件是否齐全
2. **语法与导入校验** —— AST 语法解析、未定义引用静态扫描、模块导入、接口齐备性、
   第三方依赖可用性、延迟导入策略是否生效
3. **数据库 Schema 验证** —— 建表语句、6 个业务字段、主键与索引、建表幂等性、
   跨线程可用性、读写往返
4. **模拟数据流测试** —— 伪造 ASR 文本与 DeepSeek 响应（含 ```` ```json ```` 代码块、
   前后缀说明、尾逗号、非法输出等变体），验证 JSON 解析、字段归一化、控制词过滤、
   相对时间换算、LLM 异常降级，最后跑通「ASR → 整理 → 解析 → 落库」的端到端链路
5. **状态提示与文档导出** —— 捕获标准输出核对 ⚪/🔴/⏳/💾 四个状态提示的文案；
   Markdown 条目的渲染、表头只写一次、追加不覆盖历史、导出文档的统计头与条目数；
   DOCX 导出后回读校验标题与待办列表样式；`--replay` 的 WAV 解码、重采样、振幅还原、
   循环遍数与尾部静音
6. **性能与截断** —— 默认档位（`base` + 结束词关闭）；控制词只在句尾/独立小句位置剥离
   （句中实词如"会议结束之后"必须保留）；处理期间暂停入队、恢复后继续采集、
   暂停不计入丢弃；真丢块时置位断点标记；指令扫描不阻塞主循环、只取尾部窗口、
   迟到结果被丢弃、取走即清
7. **唤醒词指令逻辑与状态流转** —— 指令识别（唤醒词、分段结束词、退出词、**作废词**，含
   **只说一遍的「小医」**与「小一」「小依」「晓依」这类同音错写，以及
   "会议结束之后""明天取消会议"这类不该误触发的实词、已失效的旧唤醒词"小记小记"）；
   优先级 退出 > 作废 > 分段；入库前把指令词从正文里剥干净；
   **用一个"按音量剧本说指令"的假 ASR + 假 VAD 跑完整状态机**：唤醒 → 录音 →
   "录音完毕"立即截断 → 回到待机 → 再次唤醒 → "退出录制"收工，
   验证两段录音各自独立、时间戳递增、每段结束都重置 VAD、全程零积压；
   再跑一遍**作废剧本**：唤醒 → "作废" → 那段既不转写也不进整理链路、计数 +1、
   状态机干净地回到待机并**能重新唤醒继续记**；以及"没喊唤醒词就绝不录音"的反向用例；
   最后让后台线程**模拟网友点按钮**，验证「结束并整理」立刻产出一段
   （reason = `网页手动结束`）而「放弃本条」一段都不产出、并干净回到待机
8. **拼音模糊匹配** —— 逐字转拼音与原文的**下标一一对应**（命中后要能按下标剪掉）；
   音近归一（`zhe→ze`、`shi→si`，且不能把 `shu` 错折成 `hu`）；
   **用实测的 ASR 错别字驱动**：`錄音完畢` / `入音完畢` / `保存這段` / `退出錄製` /
   `坐着飞` / `錯誤費` / `這條不要了` / `小一小一` / `小依` 全部照常触发；
   短指令词（`完毕`/`保存`/`好了`/`收工`/`就这些`…）连"万笔/玩闭/宝村/报存"这类
   同音错写也认，且**只认句尾**；反向用例：`会议结束之后给我打电话`、
   `明天取消会议，改到周四`、`把旧方案作废以后重新做`、`会议结束了`、
   `把这段录音听完`（逐字相似度 0.75 的近形陷阱）一个都不许触发；
   入库清洗按读音剥词且不伤正文、多候选命中时取最长
9. **音频预处理与 ASR 后端** —— 响度归一**只补不压**（够响的音频原样不动）、
   增益有上限、降噪确实压掉稳态底噪、静音段不被抬成噪声、削峰保护；
   零长 / 单点 / 全零 / 直流 / NaN·Inf / 不足一帧等极端输入**不抛异常、不产生 NaN、长度不变**；
   `AUDIO_PREPROCESS=false` 完全放行；按 AST 确认没引入 scipy/noisereduce 之类的新依赖；
   SenseVoice 的富文本标记清洗（`<|zh|><|NEUTRAL|>` …）；
   后端选择 `auto` 按可用性回退、显式配置说了算、`describe()` 可读；
   `.env.example` 收录了新增配置项且**不含真实 Key**
10. **Web 看板接口与导出** —— 页面渲染（状态胶囊、唤醒词提示、两个导出按钮、EventSource）；
   `/api/state`、`/api/memos`、`POST /api/text`（含空内容拒绝）；
   `/api/stream` 的 SSE 帧格式与"刚连上就补一份当前状态"；
   状态变化与新卡片真的会被推给订阅者；`/api/export` 的 Markdown / Word 下载
   与非法格式拒绝；**删除卡片**：`DELETE`/`POST /api/delete/<id>` 之后数据库少一行、
   `my_memos.md` 里那条（含原始文本）确实消失、文档条目数 = 数据库行数、
   广播出 `delete` + 计数减一的 `state` 事件、删不存在的 id 回 404；
   **手动收尾按钮**：页面上的两个按钮与显隐逻辑、`POST /api/control/finish|cancel`
   在录音时被受理、待机回 409、无麦克风回 503、非法动作回 400、GET 回 405，
   且 Web 线程**只置标志位、不碰音频缓冲**；
   **可编辑病历卡片**：卡片渲染出 `contenteditable="true"` / `data-field=` / `class="soap-block"`、
   **💾 保存修改 / 🔄 智能润色推演两个按钮与四条路由**（新路径注册 + 旧路径别名仍可用）、
   推演期间卡片上真的会挂出加载提示、前端会上报"学生亲手改过哪些字段"、
   空段的 `:empty::before` 占位、两个写接口都拦得住白名单外字段与 404 的主键、
   没有 DeepSeek 客户端时回 503、模型返回坏 JSON 时回 502 **且不落库**，
   以及手改内容确实会进写回提示词、写回时不碰 `raw_text` 与 `record_time`；
   **多选合并**：每张卡片有勾选框、工具栏有合并按钮且默认灰着、「已选 N 条」计数、
   加载动画文案、成功后按服务端同款排序插入新卡（不无脑 prepend）、
   勾选状态挂在页面级不随重绘丢失；`POST /api/memos/merge` 的七种参数拒绝
   （缺字段 / 不是数组 / 空数组 / 只选一条 / 重复 id 去重后不足两条 / id 不是数字 / 超上限）、
   有一条不存在就整个 404 并列出缺哪几个、无 LLM 回 503；
   合并提示词的九项要求（带教导师角色、去粗取精、融会贯通、标准 SOAP、不许造体征、
   待排口径、冲突以更晚为准、教学声明）与"**不能**出现「忠于学生的修改」"，
   两份提示词逐字共用同一段病史/诊断思考/诊疗计划/输出格式常量（抄成两份迟早改一漏一）；
   按时间先后拼接（传进去是乱的也照样排好）、逐段标注时间与出处、带上原始语音、
   空段仍按"没问到的"与"要你推演的"分开说（三条病史空了要算进"他没问到"那一句，
   八段都写了时那两句叮嘱都不出现）；
   接上假 DeepSeek 跑通真合并：按时间顺序回报 `merged`、落库、`record_time` 取最晚那段、
   源记录**一条都不删**、走 `publish_memo` 计数 +1、Markdown 重刷、广播出 `memo` 事件，
   并用页面同款 `ORDER BY` 实测"合并卡排在自己碎片上面"；
   调用失败与"合法 JSON 但八段全空"都回 502 **且不落库**
11. **医学问诊模式** —— 热词表的规模/去重/用户点名的 15 个词是否齐全；
   **解码提示词 ≤ 220 字**、点名词真的进了提示词、反义词对没被拆散、
   溢出到"仅校正"的词是少数（词表顺序 = 优先级的契约，有断言盯着）；
   两个关闭开关；**识别后校正**的 12 条正负例（含"血长规"改不动及其原因）；
   `SOAP_COLUMNS` 与两个白名单的关系、口语 SOAP 切分、`normalize_memo`/`has_soap`、
   推演输入（全量 JSON、空段分开表述、修订版排在原始语音前）；
   **病历结构（八段）**：`SOAP_SECTIONS` 就是那八段且顺序为
   主诉 → 现病史 → 既往史 → 个人史 → 家族史 → 体格检查 → 诊断思考 → 诊疗计划、
   三条病史**夹在现病史与体格检查之间且彼此独立**、`SOAP_ICONS` 恰好只给这三段发图标、
   中文标题里**不带 emoji**（病历文书要原样进 Markdown/Word，标题里不该印图标）、
   八段全部进了 `EDITABLE_FIELDS` 白名单、
   三条病史**都在 `CLINICAL_FACT_FIELDS` 里**（漏出去模型就会开始编烟酒史和家族史）；
   本地兜底切分下三条病史各自成栏互不串栏；`memo_to_dict` 给三条病史带上卡片图标；
   落库八段原样往返、**三条病史是三个独立的列**；
   **导出**：三条病史各是一个独立的三级标题、按规范顺序排在现病史与体格检查之间、
   每栏标题下面就是它自己的正文、标题里不印 emoji、空栏整段省略；
   **临床推演提示词**的十项要求（带教医师/OSCE 角色、初步诊断、支持点与不支持点、
   待查口径、检查目的、危险信号、不许凭空造体征、忠于修改、教学用途声明）
   与"输出上限放宽到 3072"；**忠于修改**的三条还原规则（改过才保护、
   诊断思考与诊疗计划不保护、清空的不拦）＋请求里缺 `touched` 时的保守兜底；
   病历列的插入/往返/白名单 UPDATE（含注入式字段名与主键保护）、
   长度截断、老库 `ALTER TABLE ADD COLUMN` 迁移与幂等（按列补，含三条新病史）

> 未安装的可选依赖（`python-docx`、`flask`、`pypinyin`）会被记为**跳过**而不是失败，
> 不计入总数。第 8 组整组依赖 pypinyin，没装时 20 项一起跳过。
> 第 11 组刻意用**独立的数据库文件**，免得 SOAP 段落渲染成 `### 主诉` 污染第 10 组
> 里对文档二级标题的计数。

## 七、常见问题

**Q：第一次运行卡很久？**
首次要下载 Whisper 模型权重（默认 `base` 约 150 MB）和 silero-vad 权重（约 2 MB），
缓存在 `~/.cache/huggingface` 与 `~/.cache/torch`；默认后端 SenseVoiceSmall 还要
从 modelscope 下约 **936 MB** 权重到 `%USERPROFILE%\.cache\modelscope`
（本机实测约 6 分钟，日志里能看到进度条）。之后启动是秒级的。

**Q：直接报 `ModuleNotFoundError: No module named 'openai'`？**
八成不是包没装，而是**跑在了另一个 Python 上**。最常见的情形：终端或 VSCode
自动激活了项目里的 `.venv`，而它是空的（只有 `pip`），于是 `python main.py`
用的是这个解释器，依赖全都不在。三步定位：

```bash
python -c "import sys; print(sys.executable)"   # 现在到底在用哪个解释器
python main.py --doctor                          # 缺什么，它逐项列出来
pip install -r requirements.txt                  # 在**上面那个解释器**里补
```

`--doctor` 会把缺失的依赖标成 `[缺失] … → pip install -r requirements.txt`。
两种收尾都行 —— 退出 venv（`deactivate`，用装了依赖的系统 Python），
或者把依赖装进 venv —— 但**别在 A 里装、在 B 里跑**。

顺带一提，`openai` 现在是**软依赖**：缺了只会退回内置规则整理，并在日志里
点名当前解释器路径，不会再让程序崩在启动那一行。

**Q：识别太慢 / CPU 占用高？**
默认已经是 `base` + 关闭结束词探测，这基本就是最省 CPU 的组合了。还嫌慢就把 `.env` 里的
`ASR_MODEL` 换成 `tiny`（快一倍，准确率略降）；`ASR_COMPUTE_TYPE` 保持 `int8`。
另外确认一下没有开着 `EARLY_STOP_KEYWORD`（`python main.py --doctor` 会显示当前状态）。

**Q：日志里出现「处理期间暂停采集，跳过 N 个音频块」？**
这是**正常现象**，不是错误：上一条还在转写/整理时麦克风暂时不收音，处理完立刻恢复。
想减少它，就让处理更快（换 `tiny` 模型、用 `--no-llm`）。

**Q：日志里出现「丢弃 N 个音频块」？**
这才是真的跟不上了 —— 消费端比采集端慢太多，队列被灌满。程序会自动作废受影响的片段
并重新开始倾听（不会卡死，但那一句会丢）。解决办法同上：换 `tiny`、
确认`EARLY_STOP_KEYWORD=false`、或提高 `QUEUE_SECONDS`。

**Q：它把我的咳嗽/键盘声也录进去了？**
调高 `VAD_THRESHOLD`（0.6~0.7），或调大 `VAD_MIN_SPEECH_MS`（如 600）。

**Q：断句太早/太晚？**
`VAD_SILENCE_MS` 控制静音阈值，默认 3000ms。说话爱停顿就调到 3500。
唤醒词模式下它只是"忘了说录音完毕"的兜底，正常用「录音完毕 / 下一条」立即切断。

**Q：老是唤不醒 / 没喊它也醒了？**
唤不醒：确认 `.env` 里的 `WAKE_WORD` 和你实际喊的一致；把 `WAKE_FUZZY_THRESHOLD`
从 `0.72` 调低到 `0.6` 会更宽容；ASR 老把它听成某个字，就把那个写法加进 `WAKE_ALIASES`。
误唤醒：调高阈值（`0.85`），或者换个更"不像日常话"的唤醒词（默认的叠词「小医小医」
已经比「开始记录」这种常用语安全得多）。
最直接的办法是开 `--web`，看页面上的状态胶囊什么时候变红 —— 一目了然。

**Q：唤醒词的识别会不会很费 CPU？**
不会。它用 `tiny` 模型、只看最近 2.2 秒、每 0.6 秒最多一次、同一时刻只有一次在飞，
而且**只在检测到人声时才扫**。没人说话时一次都不跑。更弱的机器可以把
`WAKE_SCAN_INTERVAL_SECONDS` 调到 `1.0`，代价是唤醒反应慢半拍。

**Q：录音时说的"录音完毕"会被录进正文吗？**
不会。所有指令词（唤醒词、分段结束词、退出词、作废词）都在**送 DeepSeek 之前**被剥掉，
剥完才整理入库。句中的同名实词例外保留。

**Q：说了"结束词/作废词"但没反应？**
先从这三处查：
1. **是不是说在了句子中间** —— 作废词和短结束词**只在句尾生效**
   （"明天取消会议，改到周四"是正文，不算指令）；
2. **是不是已经在待机了** —— 你先前要是说了"录音完毕"，那一段早就存完了，
   之后的"作废"作废的是空的下一条；
3. **是不是 ASR 把词写得太离谱** —— 拼音匹配能救回同音错字
   （`錄音完畢`/`坐着飞`/`錯誤費` 都认），但**救不回听错的音**：
   实测「收工」被听成「作证」「终于」（shou-gong vs zuo-zheng / zhong-yu），
   读音都变了，任何匹配算法都无能为力。换个说法（"录音完毕"）、
   或者干脆用网页上的 **⏹️ 结束并整理** 按钮。

**Q：说了"作废"但那条还是存下来了？**
同上一问的三条。如果确实是要丢掉的，说完整点："这条不要了"；
不方便开口就直接点网页上的 **❌ 放弃本条**。

**Q：我说话老爱带"取消"/"保存"，会不会把正常内容弄丢？**
作废词和短结束词都只认句尾，所以"明天取消会议，改到周四""文件我已经保存了副本"这类安全。
但如果你习惯说"……取消""……保存了"就结束一句话，那确实有风险 —— 把 `.env` 里的
`CANCEL_KEYWORDS` 改窄一点（比如只留 `作废,这条不要了`），或者把
`SHORT_END_KEYWORDS=off` 整组关掉，回到"只有长指令词能收尾"的保守行为。

**Q：识别不准，怎么调？**
先确认音频预处理开着（`AUDIO_PREPROCESS=true`，默认就是开的）——
麦克风音量偏小时它的帮助最直接。还不行就换中文专用模型：`pip install funasr`，
`.env` 保持 `ASR_BACKEND=auto`，程序会自动切到 SenseVoiceSmall
（中文专用、CPU 上更快更准，代价是几百 MB 依赖 + 首次下载约 900 MB 权重）。
`python main.py --doctor` 会打印当前实际生效的后端。

**Q：医学术语老是被听错，怎么办？**
按代价从低到高排：`ASR_HOTWORDS` 里补上你科室的常用词（**加在最前面**，
只有靠前的词才进得了 220 字的解码提示词）→ 确认 `ASR_HOTWORD_CORRECT=true`（默认开）
→ 想激活解码期提示词，把 `.env` 改成 `ASR_BACKEND=whisper` 并配 `ASR_MODEL=small`
（提示词只有 whisper 后端吃；代价是中文识别率本身可能不如 SenseVoice）。
要说明的是：**校正层要求完全同音才会改**，「血长规」这种 pypinyin 取了另一个读音的
（长 → zhǎng）它救不回来。改不了的就直接到网页卡片上改 —— 那是最后一道、也最可靠的兜底。

**Q：为什么默认没吃到医学热词的解码提示词？**
因为 `ASR_BACKEND=auto` 在本机装了 funasr 之后会落到 **SenseVoiceSmall**，
而它**没有 `initial_prompt` 参数** —— 这条优化对它是静默失效的，
真正在兜底的是识别后校正层。`python main.py --doctor` 会打印
`医学热词 = 79 个 · 解码期提示词 开（仅 faster-whisper 生效） · 识别后校正 开`，
一眼能看出当前吃没吃到。

**Q：网页上改的病历会被模型覆盖吗？**
不会。手工编辑点「💾 保存修改」就立即持久化，完全不经过模型。只有你主动点
「🔄 智能润色/推演」才会调模型，而且**你亲手打过字的那几段会被强制保留**：
页面会把你动过的字段名一起报上去，模型返回后那几段原样还原 —— 这是代码里的保证，
不是提示词里的一句请求。完成的提示会写明"你手写的 N 段已原样保留"，
被保住的段落左边会补一道绿条。

唯一的例外是**诊断思考与诊疗计划**：那两段就是按这个按钮要推演的东西，
学生自己写了还按推演，说明他想看老师的思路，所以会被模型结果覆盖。
不想被覆盖就别点这个按钮 —— 手改 + 保存是安全的。

**Q：合并之后原来的卡片还在吗？会不会把几条删掉换一条？**
**不在条数上做手脚 —— 合并只是新起一条，源记录一条都不删。** 结果就是页面上多出
一张汇总卡（排在自己那几段碎片上面），下面几段原记录照旧躺着。想清理就自己点
🗑️ 删除：合并这个动作本身不该替你做"这些碎片已经没用了"的判断，学生很可能还要
回头对照自己当时记的原话。真嫌乱，删源记录时 `my_memos.md` 会跟着重刷，
合并出来的那张不受影响（它自己就是一条独立记录）。

**Q：模型会不会替学生编出没问到的体征？**
提示词里"不许凭空创造临床事实"是第一条铁律，主诉/现病史/体格检查里的症状体征只能来自
学生写下的内容或原始语音。诊断与计划则允许推理，但一律要求写成"待排/待查"口径、
并注明依据（支持点 / 不支持点），信息不足时给的是"……待查"加"该追问什么"，
而不是猜一个病名。**这终究是教学演练**，模型输出是给学生看的思维示范，
不能当临床诊疗依据。

**Q：老的记录（没有 SOAP 八段）还能看吗？**
能。老的「标题/分类/摘要/待办」结构完整保留，病历八段对老记录是空串，
卡片上显示成灰色的「未提及 · 点击补充」、点开可以补写。
**连三条病史都没有的更老的记录也一样** —— 那三个列是后加的，
启动时用 `ALTER TABLE ADD COLUMN` 逐列补上，不动任何既有数据。

**Q：既往史、个人史、家族史为什么要分三栏，合一段不是更省事吗？**
因为这仨回答的**不是同一个问题**：既往史问「患者本人得过什么病」，
个人史问「患者本人怎么生活」（烟酒、职业、居住地），家族史问「他的亲属」。
合在一段就得靠模型去猜哪句归哪栏，而「父亲吸烟」和「本人吸烟」写反了
是带教老师一眼能挑出来的错。分三栏后判据只剩一条 —— **这句话说的是谁**。
三栏在卡片上并排显示、各自可编辑、在 Markdown 与 Word 里各自是一个标题。

**Q：删掉的卡片还能找回来吗？**
不能，页面上的二次确认就是为这个。删除会同时改数据库和 `my_memos.md`，
两者都不可撤销 —— 需要留档就先点「导出 Markdown」下载一份。

**Q：能不能用手机看网页？**
可以。`.env` 里把 `WEB_HOST` 改成 `0.0.0.0`，然后用手机浏览器打开
`http://<电脑的局域网IP>:5000`。注意这会让**同一局域网内的任何设备**都能访问这个页面
—— 它不只是只读：导出按钮能下载你全部的备忘录，删除按钮能一条条删掉它们
（目前没有登录/鉴权）。仅在完全可信的网络里这么做，看完就把 `WEB_HOST` 改回 `127.0.0.1`。

**Q：网页打不开 / 提示缺少 flask？**
`pip install flask`（约 1 MB，纯 Python）。另外确认端口没被占用，或换一个：
`python main.py --web --port 8080`。只想看网页不想开麦克风：`--web --no-mic`。

**Q：没有 API Key 能用吗？**
能。程序会提示并降级到内置规则整理（关键词分类 + 正则时间解析 + 待办抽取），
功能弱一些但数据一条不丢，之后可以用 `--text` 重跑补齐。

**Q：处理期间说的话会丢吗？**
音频在独立线程持续采集并进入 8 秒环形队列（`QUEUE_SECONDS`），所以短暂的处理延迟不会
丢音；只有持续积压超过缓冲长度时才会丢弃最旧的音频块，并在日志中提示。

**Q：`my_memos.md` 在哪里？为什么没生成？**
它和 `memos.db` 同目录，**第一次成功保存备忘录时**才创建（开跑前不会凭空出现）。
如果你用 `--db` 换了数据库位置，Markdown 仍然写在默认位置，需要一起改就加 `--md-path`。
不想要这个文件：`.env` 里把 `MARKDOWN_PATH` 留空，或运行时加 `--no-md`。

**Q：没听到蜂鸣声？**
部分终端（如 VS Code 内置终端、某些 Windows Terminal 配置）会静默忽略响铃字符，
这属于终端行为而非程序问题 —— 看 `🎙️`/`🔴` 图标同样能判断状态。不想要声音就用 `--no-beep`。

**Q：`--export-docx` 报错说缺少依赖？**
Word 导出需要额外安装 `pip install python-docx`（约 250 KB，纯 Python）。
Markdown 导出是内置的，不需要任何额外依赖。

**Q：麦克风打不开？**
Windows：设置 → 隐私和安全性 → 麦克风 → 允许桌面应用访问。
Linux：确认当前用户在 `audio` 组内。macOS：给终端授予麦克风权限。
先用 `python main.py --doctor` 确认能枚举到输入设备。

## 八、项目结构

```
.
├── main.py                  # 主程序：状态机监听 / ASR（whisper·funasr）/ 医学热词 / 拼音匹配 / 音频预处理 / SOAP 整理 / SQLite / 导出 / CLI
├── webui.py                 # 网页看板（Flask 路由 + SSE 推送 + 导出/删除/手动收尾/病历卡片编辑）
├── templates/
│   └── index.html           # 看板页面（单文件，内联 CSS/JS，无前端框架）
├── selfcheck.py             # 离线自检脚本（11 组检查，含状态机、拼音匹配、Web 接口与医学问诊模式）
├── requirements.txt         # 依赖清单
├── .env.example             # 环境变量模板（复制为 .env 使用）
├── .env                     # 你的真实配置（已被 .gitignore 忽略）
├── .gitignore
├── README.md
├── memos.db                 # SQLite 数据库（首次运行时自动创建）
└── my_memos.md              # 每条自动追加的 Markdown 流水（首次保存时自动创建）
```

`main.py` 内部按职责分层，从下往上依次是：基础工具 → 配置（含医学热词表与 SOAP 列定义）→
SQLite 存储 → 文档导出 → DeepSeek 整理（SOAP 提示词）→ 本地规则兜底 →
关键词匹配（唤醒词/指令，拼音模糊）→ 本地 ASR（含识别后热词校正）→
VAD 状态机监听 → 状态广播 → 流程编排 → CLI。

> 重型依赖（`torch` / `silero-vad` / `faster-whisper` / `sounddevice` / `openai` /
> `flask`）全部**延迟导入**，模块顶层只依赖标准库。因此即使一个第三方包都没装，
> 也能 `import main` / `import webui` 并跑通 `python selfcheck.py`。
> `webui.py` 里的 Flask 也只出现在 `create_app()` 内部，`import webui` 本身不需要 Flask。

状态机、广播器和 Web 层是这样串起来的：

```
VoiceListener.run()   ──on_status──►  AppState.set_state()    ──►  Broadcaster ──► SSE ──► 状态胶囊变色
                      ──on_cancel──►  AppState.publish_cancel()─┘                          （本条已作废）
MemoPipeline          ──on_memo────►  AppState.publish_memo()  ──┘                ──► SSE ──► 新卡片滑入
POST /api/delete/<id> ─────────────►  AppState.publish_delete()──┘                ──► SSE ──► 卡片淡出 + 计数减一
                                                ▲
                                       /api/state /api/memos  ← 页面首次加载时读取
```

三条写入路径（保存 / 作废 / 删除）走的是同一套广播，所以多个页面之间天然同步。

`Broadcaster` / `AppState` 只用 `threading` + `queue` 实现，**不依赖 Flask** ——
所以自检脚本不用起 HTTP 服务就能验证整条推送链路。
